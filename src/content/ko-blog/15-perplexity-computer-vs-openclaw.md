## 1. Perplexity 컴퓨터란 실제로 무엇인가 {#what-it-is}
핵심은 다음과 같습니다: 평이한 언어로 결과를 설명하면 컴퓨터가 그 방법을 알아냅니다. "내 레스토랑의 디지털 마케팅 캠페인을 계획하고 실행해 줘." "내 독서 기록을 추적하는 데 도움이 되는 안드로이드 앱
그 인터페이스 뒤에서, Computer는 요청을 구조화된 하위 작업으로 분해하고, 19개의 사용 가능한 모델 중 각 단계에 가장 적합한 모델에 작업을 위임하여, 일이 끝날 때까지 일부는 병렬로, 일부는 순차적으로 실행합니다.

**모델 스택:**

| 모델 | 역할 |
| --- | --- |
| Claude Opus 4.6 | 핵심 추론 및 오케스트레이션 엔진 |
| ChatGPT 5.2 | 장문 맥락 기억, 광범위한 웹 검색 |
| Gemini | 심층 연구, 하위 에이전트 생성 |
| Nano Banana | 이미지 생성 |
| Veo 3.1 | 비디오 생성 |
| Grok | 경량, 속도 민감형 작업 |

총 19개의 모델이 있으며, 위 표는 그중 주요 모델들을 보여줍니다. Opus는 오케스트레이션 레이어로서,
**환경:** 각 작업은 실제 파일 시스템, 실제 브라우저 및 사전 구축된 도구 통합에 접근할 수 있는 격리된 클라우드 컴퓨팅 환경에서 실행됩니다. 로컬 컴퓨터에서는 아무것도 실행되지 않습니다. 통합 기능은 Perplexity가 큐레이팅하며,
**가격:** Perplexity Max는 월 $200이며, 10,000 크레딧이 포함됩니다. 컴퓨터가 실행되면서 크레딧을 소모하므로 사용량은 무제한이 아닙니다. 하위 에이전트별로 지
**마케팅 문구에 대한 한 가지 주의사항:** Perplexity는 컴퓨터가 "몇 시간 또는 심지어 몇 달 동안 실행될 수 있다"고 말합니다. 이 제품은 2월 25일에 출시되었습니다. 아직 실제 워크플로우에서 수개월간 지속
> *"AI 에이전트는 놀라울 정도로 유능하지만 — 그들에게는 집도, 영구적인 작업 공간도, 자신만의 컴퓨터도 없습니다."*

Perplexity Computer는 바로 그 논제를 상업적으로 구현한 것입니다.
이것은 Perplexity가 그 게시물을 읽고 제품을 만든 것이 아닙니다. Perplexity는 블로그 #01이 공개되기 전인 1월에 내부 실험을 시작했습니다. 이는 여러 팀이 독립적으로 같은 결론에 도달했다는 뜻입니다. 그리고
| 영구적인 작업 공간 | 작업별 클라우드 파일 시스템 | `~/.openclaw/data/` |
| 다중 모델 라우팅 | 19개 모델, Opus가 오케스트레이션 | `model.fallbacks` + `modelByChannel` |
| 하위 에이전트 조정 | 작업 분해 → 에이전트 위임 | `sessions_spawn` 팬아웃 |
| 장기 실행 자율성 | 주장: 수 시간에서 수 개월 | Cron + `runTimeoutSeconds` |
| 실제 브라우저 | 내장 | `browser_snapshot`, `browser_navigate` |
| 에이전트 컨텍스트 파일 | 플랫폼 관리, 사용자에게 보이지 않음 | `SOUL.md`, `USER.md`, `HEARTBEAT.md` |
| 지출 제어 | 하위 에이전트당 크레딧 한도 | `runTimeoutSeconds` (시간 기반 프록시) |

설계 결정은 거의 일대일로 대응됩니다. 영구 저장소, 브라우저 액세스, 다중 모델 라우팅, 하위 에이전트 병렬 처리, 장기 실행 자율성 — 이것들은 Perplexity가 발명한 기능이 아닙니다. 이것들은 OpenClaw 커뮤니티가 작년부터 구성 가능한 형태로 사용해 온 기능입니다.
OpenClaw의 창시자 피터 스타인버거는 2월에 OpenAI에 합류했습니다. 알트먼은 개인 에이전트를 "우리 제품의 핵심이 될 것"이라고 설명했으며, 미래는 "극도로 다중 에이전트화될 것"이라고 말했습니다. Anthropic은 1월에 Claude Cowork를 출시했습니다. 업계 전체가 이제 OpenClaw의 오픈소스 커뮤니티가 가장 먼저 구축한 인프라 패턴을 제품화하고 있습니다.

## 3. 차이점 {#diverge}

아이디어는 동일합니다. 실행 철학은 정반대입니다.
Ars Technica는 다음과 같이 잘 표현했습니다: *"만약 OpenClaw가 AI 에이전트 도구의 오픈 웹이라면, Computer는 Apple의 앱 스토어입니다."*

그 비유는 정확하며 곱씹어 볼 만한 가치가 있습니다. 오픈 웹
| 측면 | Perplexity Computer | OpenClaw |
| --- | --- | --- |
| 실행 위치 | 클라우드 전용 | 로컬 머신, 자체 호스팅 VPS 또는 TinyClaw |
| 통합 모델 | 선별된 플랫폼 통합 | Open Skills + MCP 생태계 |
| 구성 | 플랫폼 관리, 사용자에게 보이지 않음 | `openclaw.json`, 완전한 사용자 제어 |
| 보안 모델 | 플랫폼이 책임짐 | 사용자가 책임짐 |
| 사용자 정의 한계 | 낮음 — Perplexity가 제공하는 것만 사용 | 높음 — 무엇이든 구성 가능 |
| 투명성 | 블랙박스 | `sessions_history`를 통한 전체 기록 |
| 데이터 위치 | Perplexity의 클라우드 | 사용자의 기기 또는 서버 |
| 지출 제어 | 하위 에이전트별 크레딧 한도 | `runTimeoutSeconds` (시간 프록시) |

이러한 상충 관계는 일관되게 한 방향으로 작용합니다: Perplexity는 단순성과 안전성을 얻는 대신 제어권을 포기하고, OpenClaw는 제어권과 확장성을 얻는 대신 단순성을 포기합니다.

## 4. Perplexity가 할 수 없는 것 {#cant-do}
이것들은 특수한 사례가 아닙니다. OpenClaw 사용자들이 기본으로 여기는 기능들입니다.

**SOUL.md — 지속적인 에이전트 정체성**

OpenClaw에서 `SOUL.md`는 모든 세션에 걸쳐 에이전트가 생각하고 행동하는 방식을 형성하는 파일입니다. 한 번만 작성하면 됩니다: "당신은 항상 출처를 인용하고, 요약본보다 원본 문서를 선호하며, 불확실성은 명시적으로 표시하는 연구 조수입니다." 모든 세션은 해당 컨텍스트가 이미 로드된 상태로 시작됩니다.
Perplexity Computer에는 동등한 기능이 없습니다. 모든 작업은 플랫폼의 기본값에서 시작됩니다. 영구적인 지침 세트를 작성하거나, 에이전트가 모호함을 처리하는 방법을 정의하거나, 지속되는 캐릭터를 부여할 수 없습니다. 오늘 작업하는 에이
OpenClaw는 스케줄된 워크플로우를 자율적으로 실행합니다. "매주 평일 오전 7시 50분에 어제의 GitHub 활동을 가져오고, 검토가 필요한 PR들을 요약한 뒤, 요약본을 텔레그램으로 푸
OpenClaw는 `/hooks/agent` 엔드포인트를 제공합니다. PR이 열리면 GitHub Webhook이 실행되고, 에이전트는 diff를 읽고 리뷰를 실행한 후 Slack에 피드백을 게시합니다 — 이 모든 과정은 사람의 개입 없이 이루
워크플로가 로컬 리포지토리에서 코드를 읽거나, 파일 시스템의 문서를 처리하거나, 로컬 애플리케이션과 상호작용하는 등 사용자의 머신에 있는 파일을 다루는 경우, Perplexity Computer는 이러한 파일에 접근할 수 없습니다. 모든 것은 Perplexity의 클라우드 환경에서 실행됩니다. 사용자의 로컬 머신은 Perplexity Computer에 보이지 않습니다.

**서드파티 스킬 및 MCP 서버**
OpenClaw의 생태계에는 ClawHub와 agentskills.io에 있는 수천 개의 스킬과 맞춤형 MCP 서버 지원이 포함됩니다. 내부 도구에 연결되는 스킬을 설치하거나, 조직의 워크플로를 담은 맞춤형 스킬을 작성하거나
OpenClaw의 `sessions_history`는 모든 도구 호출, 모든 모델 응답, 모든 결정 지점 등 에이전트가 수행한 모든 작업에 대한 완전하고 검사 가능한 기록을 제공합니다. 문제가 발생했을 때, 정확히 무슨 일이 일어났는지 확인할 수
## 5. Perplexity가 더 잘하는 것 {#does-better}

월 200달러의 가치가 무엇인지 솔직하게 따져보는 것은 중요합니다. 이 중 몇 가지는 단순한 마케팅이 아닌 실제 장점입니다.

**설정 불필요**

프로비저닝할 서버가 없습니다. 구성할 `openclaw.json` 파일이 없습니다. 관리할 API 키가 없습니다. 디버깅할 MCP 연결이 없습니다. 브라우저를 열고 원하는 것을 설명하면 컴퓨터가 작업을 시작합니다.
OpenClaw에서는 TinyClaw가 인프라를 처리하더라도, 채널 연결, SOUL.md 작성, 모델 스택 구성, Cron 스케줄 결정과 같은 상당한 설정 단계가 여전히 있습니다. 비기술적인 사용자에게 이 격차는 상당합니다.

**신
Opus는 19개의 모델 중 어떤 모델이 각 하위 작업을 처리할지 결정합니다. 사용자는 "리서치에는 Gemini를, 이미지에는 Nano Banana를, 가벼운 작업에는 Grok를 사용하라"와 같이 지정하지 않습니다. 해당 라우팅은 Perplexity의 시스템이 가장 효과적이라고 판단한 것에 따라 자동으로 이루어집니다.
OpenClaw에서는 동등한 멀티 모델 라우팅을 구축하려면 `subagents.model` 설정, `modelByChannel` 사용, `model.fallbacks` 작성, 그리고 잠재적으로 `AGENTS.md`에 사용자 지정 라우팅 로직을 작성하는 등 의도적인 설정이 필요합니다. 가능은 하지만 — 작업이 필요합니다.

**하위 에이전트별 지출 한도**
이것이 Perplexity가 가지고 있지만 OpenClaw에는 명시적으로 없는 유일한 영역입니다. 크레딧 기반 지출 한도를 사용하면 "이 연구 하위 작업은 X 이상을 지출해서는 안 됩니다"라고 설정할 수 있습니다. 이는 작업 수준에서 직접 달러 단위로 비용을 제어할 수 있다는 뜻입니다.

OpenClaw의 비용 제어는 시간 제한(`runTimeoutSeconds`)을 통해 작동하는데, 이는 직접적인 지출 한도가 아닌 지출에 대한 대리 지표입니다. "$0.50를 사용하면 중지"라고 지정하는 필드가 없습니다. Perplexity Computer에는 그 필드가 있습니다.

**작동하는 사전 구축된 통합**
브라우저, 코드 실행, 이미지 생성, 비디오 생성 — 이것들은 디버깅이나 자격 증명 관리 없이 바로 작동합니다. OpenClaw에서는 각 기능에 Skill 설치, MCP 서버 구성, 또는 API 키 중 하나가 필요합니다. 일단 구성되면 결과는 더 강력하지만,
ClawHavoc 사건은 그 위험을 가장 명확하게 보여주는 예시입니다. 2026년 2월, 조직적인 공급망 공격을 통해 ClawHub에서 341개의 악성 스킬이 발견되었습니다. 주요 페이로드는 Atomic Stealer(AMOS)로, 암호화폐 지갑, API 키, 브라우저 비밀번호를 표적으로 삼는 macOS 자격 증명 탈취 프로그램이었습니다. 약 30만 명의 활성 OpenClaw 사용자가 잠재적으로 노출되었습니다. 단지 7일의 계정 연령과 GitHub 계정만 요구하는 ClawHub의 개방형 업로드 모델은 공격자들이 대규모로 게시하는 것을 매우 쉽게 만들었습니다.
Perplexity Computer의 폐쇄형 모델은 이러한 공격 표면을 완전히 제거합니다. 어떤 스킬도 설치할 수 없기 때문에 악성 스킬을 설치할 수 없습니다.

**상업적 책임**

월 200달러를 내면 지원 계약, SLA, 그리고 제품이 사용자에게 손해를 입히는 방식으로 고장 났을 때 책임을 지는 조직을 얻게 됩니다. OpenClaw는 오픈소스입니다. TinyClaw는 자체 지원 모델을 갖춘 호스팅 서비스입니다. 하지만 둘 다 대기업의 주력 유료 제품과 동일한 책임의 무게를 지니지는 않습니다.

## 6. 실제 각 제품의 대상 사용자 {#who-for}

이것들은 동일한 사용자를 두고 경쟁하는 것이 아닙니다. 이들을 경쟁자로 보는 것은 어느 것을 사용해야 할지에 대한 잘못된 결론으로 이어지기 때문에 이 점은 중요합니다.

**Perplexity 컴퓨터:**
Perplexity Computer로부터 가장 큰 혜택을 받는 사용자는 클라우드 기반 워크플로우를 가지고 있고, 로컬 파일을 건드리거나 외부 이벤트로 트리거할 필요가 없으며, 플랫폼이 모든 라우팅 및 인프라 결정을 관리하는 것에 불편함이 없고,
경쟁사 조사를 자동화하는 마케팅 컨설턴트. AI를 사용하여 리서치와 초안 작성을 보조하는 작가. 전적으로 클라우드 서비스에 존재하는 고객 커뮤니케이션 워크플로우를 자동화하고 싶어하는 소규모 사업자. 이러한 사용자들에게 OpenClaw 구성 레이어는 가치가 아니라 마찰일 뿐입니다. Perplexity Computer는 월 200달러에 그 마찰을 제거합니다.

**OpenClaw:**
OpenClaw로부터 가장 큰 혜택을 받는 사용자는 로컬 파일 접근, Cron으로 트리거되는 자율 워크플로우, Webhook 기반 이벤트 처리, 독점 도구를 위한 맞춤형 스킬, 또는 'Perplexity의 클라우드에서 실행'을 애초
PR 리뷰 봇을 원하는 엔지니어, 로컬 리포지토리의 코드로 작업하는 에이전트가 필요한 개발자, 내부 인프라에 대해 실행되는 자율 모니터링 워크플로우가 필요한 운영팀, 그리고 SOUL.md 파일에 세션
가장 명확한 구분법은 다음과 같습니다. 워크플로우가 사람의 입력 없이(Cron 또는 Webhook) 시작해야 하거나 Perplexity의 클라우드에 없는 파일을 다뤄야 한다면 당신은 OpenClaw 사용자입니다. 만약 워크플로우를 당신이 직접
## 7. 이것이 에이전트 플랫폼 경쟁에 의미하는 바 {#platform-race}

**인프라 논제는 결론이 났습니다.**

2025년 초, '에이전트는 자신만의 영구적인 컴퓨팅 환경이 필요하다'는 것은 논증이 필요한 주장이었습니다. 2026년 2월, 이는 Perplexity가 월 200달러에 판매하는 제품이 되었고, OpenAI는 로드맵에 포함시키고 있으며, Anthropic은 Claude Cowork라는 이름으로 출시하고 있습니다. 이것이 실제 제품 카테고리인지에 대한 논쟁은 끝났습니다. 이것은 실제 제품 카테고리입니다.
이제 경쟁은 인프라 계층의 존재 여부가 아니라, 누가 그 계층을 소유하느냐를 두고 벌어집니다.

**오픈 소스-상업용 파이프라인은 예정대로 가동되고 있습니다.**
OpenAI는 OpenClaw의 개발자를 고용했습니다. Perplexity는 그 컨셉을 기반으로 제품을 만들었습니다. Anthropic은 Claude Cowork를 만들었습니다. 이 패턴은 Linux → Red Hat → AWS, Android → Samsung, Git → GitHub에서 일어났던 일과
OpenClaw 생태계에 던져볼 만한 질문은 다음과 같습니다. 폐쇄적이고 잘 다듬어진 버전이 개선됨에 따라, 개방적이고 구성 가능한 버전이 그 독자적인 가치를 유지할 수 있는가? 역사적으로 그 대답은 '그렇다'입니다 — 하지만 가치 제안은 명확하게 유지되어야 합니다. "완벽한 제어, 모든 인프라, 확장 가능한 생태계"는 일관성 있는 입장입니다. "설정이 더 필요한, 약간 더 저렴한 Perplexity Computer 버전"은 그렇지 않습니다.

**월 200달러에 크레딧 한도를 두는 것은 시장이 감당할 수 있는 수준을
이것이 바로 가장 세련되고, 별도 설정이 필요 없으며, 19개 모델이 조율된 이 기능의 버전에 대한 현재 가격입니다. 여기에는 10,000 크레딧이 포함되어 있으며, 무제한 사용은 아닙니다.
TinyClaw는 동일한 기본 다중 에이전트 아키텍처를 1분 이내에, 훨씬 저렴한 비용으로 배포하며, Cron 스케줄링, Webhooks, 로컬 파일 액세스 및 전체 OpenClaw Skills 생태계를 이용할 수 있습니다. 가치 제안은 "더 저렴한 Perplexity Computer"가 아닙니다. Perplexity Computer가 의도적으로 제외하는 기능이 필요한 사용자를 위한 다른 제품입니다.
시장은 실재합니다. 인프라 경쟁이 시작되었습니다. OpenClaw는 그 개념을 증명한 오픈소스 프로토타입이었습니다. Perplexity Computer는 이에 대한 최초의 주요 상업적 투자 중 하나입니다. 앞으로 더 많은 것을 기대하세요.
