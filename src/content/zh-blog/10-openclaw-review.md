OpenClaw 有 207,000 个 GitHub Stars。这个数字每天还在增加大约 2,000 个。

这意味着很多人在观望。而每周都会冒出新的"一键部署 OpenClaw"服务。有 EasyClaw——实际上有五个不同产品用这个名字，有 InstaClaw，有官方托管版 OpenClaw Cloud，有两个都叫 TinyClaw 的 GitHub 仓库。还有最初的那个：在自己的硬件上自托管，这才是这个项目最初设计的用途。

问题不在于选项太多。而在于大多数测评都没告诉你：过了落地页之后，真实体验是什么感觉。

所以我们都测了。两周，五种方案，用真实任务跑。以下是结果。

---

## 测试范围与方法

五种方案：

1. **自托管 Mac Mini M4** — 标准方案
2. **自托管 VPS** — Linux 云服务器，纯 SSH 操作
3. **TinyClaw** — AgentPuter 的云运行时，一键部署
4. **OpenClaw Cloud** — 官方托管版，$9.99/月
5. **EasyClaw.ai** — 三档管理托管（$5–$49/月）

每种方案，我们测量了：
- **到第一条消息的时间**（从零到能和 Agent 对话）
- **7 天稳定性**（在线率、消息丢失、重启行为）
- **功能完整性**（什么真的能用，什么需要额外配置）
- **真实任务表现**（邮件整理、日历管理、网页研究）
- **月度成本**（中等使用量，每天活跃使用约 2 小时）

模型全程使用 Claude Opus 4.6，除非某个方案只提供其他模型。所有测试以 Telegram 为主要渠道，因为它在所有平台上最稳定。

---

## 方案一：自托管 Mac Mini M4

**到第一条消息：** 22 分钟  
**7 天在线率：** 100%  
**月度成本：** ~$35（API）+ $0（硬件摊销）

这是基准线，它设定了一个很高的标准。

安装是一行命令——`openclaw onboard --install-daemon`——向导会引导你完成每一步。瓶颈不在软件，在 API Key 管理和 Telegram Bot 设置，如果你以前没弄过，这部分大约要 10 分钟。

一旦跑起来，Mac Mini 在几件事上就是比所有云端方案强。通过 BlueBubbles 集成 iMessage，没有任何其他方案能做到。语音唤醒（Voice Wake）让你通过原生 macOS App 免提跟 Agent 说话——所有云端部署都没有这个。本地文件系统访问意味着你的 Agent 可以处理永远不离开你机器的文件。

SOUL.md 文件让这个体验开始感觉和其他方案不同。它不是提示词，是你的 Agent 每天启动时读取的持久身份文件。测试一周后不断添加内容，Agent 已经知道我的日程、沟通风格、邮件回复偏好，知道哪些日历事件我认为可以跳过。这种语境的积累不是在会话层面发生的——它是复利式的。

有一个麻烦：通过 BlueBubbles 的 iMessage 认证比较折腾，测试中每 2–3 周需要重新登录一次。`openclaw doctor` 命令会在你漏掉一天消息之前捕获这个问题，但你需要主动去跑它。

如果你有 Mac Mini 或愿意买一台，这是最终答案。功能上限比任何托管选项都高。

## 方案二：自托管 VPS（Linux）

**到第一条消息：** 28 分钟  
**7 天在线率：** 100%  
**月度成本：** ~$35（API）+ $6（VPS）

对于想要 Root 访问权限的 Linux 用户和开发者来说，这等同于 Mac Mini 方案，只是没有语音唤醒和 iMessage。安装过程一模一样，区别是你在维护一台服务器而不是一台桌面机。

优势是天然的远程访问。无论你的笔记本是否开着，Agent 都可以访问。Tailscale Serve 或 Funnel（官方推荐的方式）让这件事变得安全，而不需要直接暴露 Gateway 端口。

缺点是运维负担。当你的 Agent 在凌晨 2 点停止响应，你要 SSH 进服务器查日志。如果你能接受这个，这是一个扎实的选项。如果不能，跳到托管方案。

值得记一下：Docker 沙箱化——OpenClaw 推荐用它来隔离 Agent 的 Shell 访问——在 VPS 上会增加可感知的延迟。聊天回复没问题。涉及文件操作或网页浏览的任务，测试中比 Mac Mini 慢 15–30 秒。如果你不担心 Agent 本身的安全隔离，不用 Docker 跑明显更快。

和 Mac Mini 同等能力，更灵活，也更多维护工作。最适合已经在管服务器、不想再多学一件新东西的开发者。

## 方案三：TinyClaw

**到第一条消息：** 48 秒  
**7 天在线率：** ~99.9%  
**月度成本：** $49.99/月（含模型）

TinyClaw（[tinyclaw.dev](https://tinyclaw.dev)）是 AgentPuter 的 OpenClaw 云运行时。每个用户获得一个独立容器，而不是共享算力。实际效果是：不会因为其他一百个用户同时发消息让你的 Agent 响应时间崩掉。

引导是我们测试的所有方案里最快的——Google 登录，选 Telegram，粘贴 Bot Token，48 秒后收到第一条消息。七天内有一次约 4 分钟的维护窗口，提前通知了。

响应时间平均 6–8 秒，保持稳定。这是独立容器相对共享算力的实际优势：不是在理想状态下更快，而是在状态不理想时不崩。你家 Mac Mini 的网络连接是个变量；云容器的不是。

Skill 安装稳定。我们从 ClawHub 测试的 12 个 Skill 中，11 个安装顺利。唯一的失败是需要 OAuth 回调配置的 Spotify 集成——这在任何平台上都需要手动设置。

没有语音唤醒，没有 iMessage，没有本地文件系统。这是云端部署的结构性限制，不是 TinyClaw 特有的。如果你需要这些，只有自托管一条路。

如果你考虑扩展到单个 Agent 以上——不同项目用不同 Agent，或者团队共享访问——AgentPuter 的背景就有意义了。同一套基础设施支持在一个账号下运行多个实例，虽然基础计划不包含这个，但路径是通的。

## 方案四：OpenClaw Cloud

**到第一条消息：** 2 分 10 秒  
**7 天在线率：** ~98.4%  
**月度成本：** $0（免费档，每月 14 算力天）或 $9.99/月 Pro

OpenClaw Cloud（open.claw.cloud）是官方背书的云版本。最主要的区别是免费档：每月 14 天算力时间，由 Kimi K2.5 驱动。需要说明的是，我们测试时 $9.99/月的 Pro 方案还是「Coming Soon」状态，所以这部分主要基于免费档的体验。

免费档不是缩水版试用。你得到预装 Skill、Telegram 集成、持久记忆、浏览器自动化，以及一台专属于你的虚拟机。14 天算力用完后 VM 关机，但数据不删。等到有新的免费时间或者 Pro 方案上线，开机就接着用。

Kimi K2.5 这个问题值得单说。日常任务——整理邮件、处理日历、起草回复——测试中感受不到和 Claude Opus 4.6 的差别。在复杂多步骤推理上，比如"研究三个竞品的定价策略，起草一份对比建议"，Claude 的连贯性明显好一些。但如果你跑的是轻量工作流，Kimi K2.5 的性价比很难反驳。

引导比 TinyClaw 多一点步骤，因为你在 Web 仪表盘里配置而不是向导。连 Telegram 大约 2 分钟。Skill 管理完全暴露，懂的人会喜欢，不懂的人会懵。

最便宜的入门路径，没有之一。想先试再决定，从这里开始。

## 方案五：EasyClaw.ai

**到第一条消息：** 4 分钟  
**7 天在线率：** 99.1%  
**月度成本：** $19–$49，取决于档位

EasyClaw.ai 的特点是浏览器桌面访问——在浏览器标签页里看到你 Agent 容器的完整桌面环境。你可以登录需要浏览器认证的账号、安装工具、修改配置文件，做托管服务通常不让你碰的东西。

我们用这个设置了一个需要浏览器认证流程的 Gmail 集成——在没有桌面访问的平台上，这一步没有别的办法做到。

定价分三档：$5/月（开发者，自带 VPS）、$19/月（托管）、$49/月（全托管含更高级支持）。到 $49/月，你已经快接近自己管一台 VPS 在经济上划算的临界点了——除非你真的不想动手。

名字要注意：至少有五个不同产品都叫"EasyClaw"某种变体——easyclaw.ai、easyclaw.app、easyclaw.pro，还有几个。我们测的是 easyclaw.ai。其中至少一个同名服务在 2026 年 2 月初的社区里引发过安全质疑。填任何凭据之前，先确认你在的是哪个网址。

## 开源变体版图

除了托管服务，开源衍生版值得了解，尽管它们面向更窄的受众。

**TinyClaw（jlia0 版）** 是在约 400 行 Shell 脚本里重新实现 OpenClaw 概念——用 Claude Code 和 tmux 搭建，而不是 Node.js 和完整框架。它通过文件消息队列同时在 Discord、WhatsApp 和 Telegram 上并行运行多个隔离 Agent，防止竞争条件。整个代码库一个下午能看完。截至 2026 年 2 月，约 2,000 个 GitHub Stars。如果你想从机制层面理解 OpenClaw 在做什么，或者需要把 Agent 嵌入受限环境，从这里入手是最直接的。

**TinyClaw（warengonzaga 版）** 是一个完全不同的项目——用 TypeScript 重写，明确把自己定位为"完全独立的产品和 OpenClaw 的替代方案"。强调插件架构、自我改进记忆、智能查询路由来降低 LLM 成本。任务执行感弱一些，个人 AI 陪伴感强一些。值得关注，但还早期。

这两个都不直接和托管服务竞争。它们是给想理解和修改底层机制而不只是使用输出结果的开发者用的。

## 我们实际会怎么选

没跑过 Agent 的：从 OpenClaw Cloud 开始。免费档给你 14 天全功能体验，一分钱不用花，一行命令不用打，搞清楚这东西是不是你需要的。

确定要的、想稳定跑起来的：TinyClaw 是最干净的选择。独立容器，响应一致，引导最快。如果你以后想跑多个 Agent 或者团队用，基础设施也是现成的。

数据主权是核心要求的，或者需要语音唤醒、iMessage 的：自托管，Mac Mini 是最合理的硬件，$599，待机 3–4W，原生跑 macOS。没有任何云方案能给你本地部署带来的东西。

想搞懂机制的开发者：先读 jlia0 的 TinyClaw 代码。400 行 Shell 脚本告诉你的比任何文档都多。

## 诚实的总结

「能用」和「有用」不是一回事。我们测试的每个方案在第一个小时内都能用了。有用需要更长时间——需要 SOUL.md 积累语境，需要连接你真正在用的工具，需要给它真实的任务而不是演示用的提示词。托管方案让你更容易开始；自托管方案在你开始之后给你更多可用的东西。

Skill 生态是目前最大的不确定因素。安全公司 Koi Security 在 2026 年 2 月初审计了 ClawHub，在 2,857 个 Skill 里发现了 341 个恶意的——大约 12% 的目录，其中绝大部分来自一个账号，一周内发布了 314 个伪装成常用工具的 Skill。OpenClaw 事后增加了审核流程，但目录太大，靠人工不够用。对待社区 Skill 就像对待浏览器扩展一样：有用，通常很好，但在装任何需要系统访问权限的东西之前，先看一眼源码。

207K GitHub Stars 说明它做对了什么。这个「什么」值不值得你花一周去验证，是本文回答不了的问题——只有你自己能答。
